## 1　候选域与唯一主选解

**覆盖声明。** 08 的 **8,112** 个候选全部经典枚举，15 个批次完成离线整数审计。12 的 **1,587** 个盲候选全部进入拟提交的三个候选字典，每张 529 个。云端返回只能证明实际返回了哪些解。对每个候选均被服务访问、服务遍历了全域或硬件证明了全局最优，均无观测依据。

每族按冻结 A/B 轴行主序选取官方允许 ID，分成 40 个连续组，9 组各 14 个候选，31 组各 13 个候选。共 489 个自由自旋和一个共享参考位。各批独立定标量化成本 \(q\)。能量 \(E(s)=-s^\top Js\)，相对本批整数基态 \(E_0\) 的残差为 \(d=E(s)-E_0\)。

**每个服务任务只产生一个主选解。**

1. 保存原返回序和原始向量。逐条核验维度、符号取值、参考位与本地整数能量。任一向量格式不符合合同，整份回包不进正式质量统计。按共享参考位校正后，40 个组全部合法才是严格向量。
2. 在严格向量中，选择**本地整数能量最低者**；同能量取**原返回下标最小者**。此处不得按 ID、原表 regret 或材料身份二次择优。
3. 只在所选向量内部从每组提取候选，按 \((q,\text{冻结行主序索引})\) 选唯一赢家，再用该候选的官方 ID 回查原表。记录主向量返回下标、整数能量、残差、主 ID 和切片 regret（原预测减本切片唯一最小预测）。
4. 技术完整但无严格向量时，主下标、主 ID、主残差和主 regret 均记 `NA`。部分链提取单列探索性字段。

严格返回集中“存在命中”和集合内最小 regret 都是**次要指标**。高能量向量恰好命中时，次要指标可为真，主解仍可能错选。禁止跨向量拼接链、从不同向量抽取候选充当主终点或用修复数据代替原主选。只有三个切片各有一个主 ID 后，才以这三个 ID 的 \((\widehat V,\text{官方 ID})\) 聚合，报告次要业务答案。

## 3　独立证书、精确包络与可达性

对切片内候选 \(c\)，令 \(D(c)\) 为能按固定规则解码出 \(c\) 的**严格合法**向量的最小整数残差。固定 \(c\) 所在链的选择，其余链只保留键值不小于 \((q_c,i_c)\) 的候选，各自取最低合法能量。某链无可选项时令 \(D(c)=+\infty\)。定义

\[
E(d)=\max_{c:\,D(c)\le d}\{\widehat V(c)-\min\nolimits_X\widehat V\}.
\]

最小值取当前 X 切片。独立检查器从归档整数矩阵和链映射重建合法位置的能量，对每个候选独立求最低可达残差。对全部 **921** 个有限 \(D(c)\)，再通过见证位串的实际跃迁识别候选、重算原矩阵能量和严格性，要求身份、能量与下界三者一致。其余 **666** 个候选逐项检查是否有其他组的最大允许键仍小于目标键。该检查器不导入生成器解码函数，也不按原始预测打破量化并列。

## 5　保留原矩阵与架构对照

定义严格保证界
\[
H=\min\{\Delta_{\mathrm{illegal}},\Delta_{\mathrm{strict\ wrong}}\}.
\]
优化目标是在 G1 通过、精确保留原最优、整数耦合绝对值不超过 127 的条件下最大化 \(H\)，同值优先保留更多不同业务层级。比较三种单调塑形，包括原折点、以赢家链内最小竞争差距设折点、以全切片第二名差距设折点；量化上限比较 31、47、63、84、95、111、127，取整比较最近偶数和半格向上。各切片按实际参考边求可行链耦合上限，再重算证书。

**上界证明。** 在候选单份、赢家所在组至少有两个候选、合法能量差为 \(4\Delta q\)、\(0\le q\le127\) 的编码类中，从任一精确基态只改变赢家所在组，选一个非赢家，其他组保持局部最优。所得输出必然错选，其能量上升不超过 \(4\times127=508\)。因此 \(H\le508\)，表中已有达到上限的构造。证明限于上述编码类。

保留三张主矩阵的依据有三项。第一，NO₂ 的 529 个允许 ID、逐位预测、量化成本、40 个组及矩阵与 P2 的 11 盲池逐位相同，维持跨阶段、同矩阵回归条件。第二，最大裕度 508 的构造利用已知赢家位置，作为答案感知对照单列。第三，保留原折点扩大可用整数范围时，原始 \(H\) 增量的大部分可由系数量程解释。

势垒按**固定参考位的单链状态**定义为经单自旋翻转到任一更低能态时，所需的最小额外爬升。上表按具有正势垒的起点计数，三族各有 369、405、360 个此类局部微观状态。它不等于允许翻转共享参考位的整机动力学势垒。

平衡量不能预测 SA 终态。平衡分布由固定矩阵及温度确定；有限退火日程的终态取决于冷却过程的冻结动力学。\(T=80\) 的数值只作为平衡谱内的一行，禁止与退火终态命中率直接比较。当前证据不足以定位具体冻结时刻，也不据云端筛选返回集拟合“有效温度”。

## 8　额度、首槽技术门和截止时间

历史余额为 550 的 11 次、1000 的 2 次。九个正式任务用于三轮三切片的完整配对。没有独立先导，首个 O₃ 即为正式槽。

| 轮次 | 第一槽 | 第二槽 | 第三槽 |
|---|---|---|---|
| 1 | 01 O₃ | 02 FO₂ | 03 NO₂ |
| 2 | 04 FO₂ | 05 NO₂ | 06 O₃ |
| 3 | 07 NO₂ | 08 O₃ | 09 FO₂ |

首槽只核验锚定输入、独立服务器 ID、完整原回包、向量格式、可复算整数能量和实际扣额。质量不用于放行。即便首槽无严格解、错选或残差很高，只要技术合同完整并已对账，即可继续。首槽过门后，同轮其余槽连续创建；每次创建后先取得唯一服务器 ID，核对该次实际扣额，再放行下一槽。此后正常排队期间无须等上一槽的质量评分或终态。发生已知技术异常即暂停。

| 状况 | 冻结处置 |
|---|---|
| 创建超时、是否受理不明或 ID 不明确 | 只查询既有请求。重复服务器 ID 只可支撑一个独立任务，保留重复槽的原记录。不同任务返回相同向量允许单独记录 |
| 扣额与路由 | 分别核对 550/1000 的前后余额、扣额与本次创建的唯一归因。期望为 550 减 1、1000 变化 0。扣费不明或异常即暂停，默认路由动用 **1000 余额立即暂停** |
| 回包损坏或违反数学证书 | 一次即暂停新创建，保留原数据。例子包括向量维度或域异常、负残差、严格点高于包络、低于非法界却出现非法组 |
| 质量差、无严格解、连续超过 P95 | 保留主次指标和单侧标签，按原槽序推进。质量偏差不触发修复、换矩阵或重提 |
| 550 的 10、11 | 仅供另行批准的技术故障诊断，禁止用来重提或替代失败的正式槽 |
| 1000 的两次 | 仅为另批架构扩展保留，795 自旋方案需另证和核验后端 |

**首次创建前锚定，首个回包后全面冻结。** 首个回包出现后，解码规则、单侧参照、判定阈值、图表规格和槽位分配一律不再变更。只追加原始服务记录、实际扣额、状态及基于同一版本计算的观测。北京时间 **2026-11-29 18:00 停止发起新任务，21:00 冻结主结果快照**。停发后只查询已建任务，快照后的终态另列。

## 10　封存回执与来源核验

机器回执按文件记录 SHA‑256，绑定最终规范、统计协议、独立检查器、三张主矩阵及字典、见证、08 并列对照、20 成员记录、单侧参照的历史汇总及预定槽位。源预测池和 P2 对照按来源哈希核验。O₃、NO₂、FO₂ 的矩阵指纹按小端 int64、行主序原始字节计算，前三个 16 位前缀依次为 `beb1d7e6715c5420`、`f72fbc9e425ebc1f`、`3502da271cd352e7`。数字指纹与具体文件容器摘要分别记录。

在仓库根目录，用已安装 NumPy 的 Python 从 Git 历史提取首次写入回执的完整提交号。与交付时公布的锚定提交号核对后运行：

~~~sh
P3_ANCHOR=$(git rev-list --reverse HEAD -- evidence/p3/receipt.json | head -n 1)
/usr/bin/python3.10 -B evidence/p3/verify.py --anchor "$P3_ANCHOR"
~~~

核验对象包括回执的 Git 锚定身份、文件字节及全部数学见证。运行目录里后起的回执或只在封存前执行的数学自检不能充当首次创建的授权凭据。交付入口为[独立检查器](../evidence/p3/verify.py)、[正式统计协议](../evidence/p3/protocol.py)、[机器回执](../evidence/p3/receipt.json)。
