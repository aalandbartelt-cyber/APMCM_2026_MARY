# P2_PLAN1 双审合并裁决（侦察兵一审 + Perplexity 二审 7.pdf）

## 总判：修订后实施。数学主线无致命错误，但统计与冻结纪律有 8 项必修——不是"五项小修"

## P 二审抓到的一审漏网（重大）
1. **分母不闭合**：20 正式任务/失败照扣/不得补足/pending 并存——必须定义两套指标：
   端到端成功率（分母=全部已提交含失败）与条件硬件质量（分母=有效回包，显式标注条件化）；
   20 个任务编号为"尝试槽位"，未启动/失败/pending/完成分别记录
2. **幸存者偏差**：无可行解任务 regret 记 NA 后会在均值/箱线图中被静默删除——
   必须两部报告（全任务可行率+条件 regret 分布显式标注条件），主图用"取得可行解且 regret 纳入的任务"口径
3. **"零调参"措辞不实**：四配置择一本身是预登记的实例级表示选择，有选择成本——
   改为"无新增模型/温度搜索；允许四预登记表示的确定性选择，全部成本公开"
4. **矩阵冻结时序漏洞（最精彩的一击）**：当前顺序"审计→SA→冻结"留了人为通道——
   人看到 SA 结果后可能通过解释证书超时/修改 tie 口径/重跑 mutate 间接改变入选配置。
   必须改为：审计→**自动选择脚本执行+不可覆盖回执**（四配置矩阵哈希/审计结果/选择指标全表/
   配置ID/代码哈希/时间戳）→SA/CIM
5. **mutate 随机性未冻死**：版本/种子/起点/tie 规则/超时行为全冻结；
   首次有效输出不得因效果差重跑——"生成多个 M8 取最好"绝禁
6. **Top-20 tie 口径未定义**：整数能量可能大规模并列，tie 规则不定则选择可被 hash 左右——预定义双 tie 规则
7. **证书状态四分类**：CERTIFIED/COUNTEREXAMPLE/UNKNOWN/IMPLEMENTATION_ERROR——
   超时=UNKNOWN 不是失败，UNKNOWN 必须公开（否则像把算得慢当数学错误淘汰）
8. **聚类 bootstrap 降调**：20 群是小样本情形（wild cluster bootstrap 文献），
   任务散点为主、二项区间附假设、bootstrap 为辅助；不做"CIM 显著优于 SA"确认性结论
