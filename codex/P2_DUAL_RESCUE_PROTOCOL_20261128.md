## 2. 路径甲：恰好两个单发 mutate

- 候选按 raw、rc 顺序登记：`A-raw-M8`、`A-rc-M8`，都用 λθ、禁选填值 R。
- 冻结输入 QUBO Q 和由原转换公式生成的完整 Ising J；SDK API 接收 J 而不是 Q。与 rescue1 原构造／N8 精确交叉核对，之后才启动调用。
- SDK 1.4.4：`perform_precision_adaption_mutate(J, iterations=100, heuristic='greedy', decision='heuristic')`，每编码一次顶层调用。函数内部 100 次迭代是获批参数，禁止第二次顶层调用或追加迭代。
- 外部 Python/NumPy 种子沿用 v2 的盲池编号 raw=240028、rc=240029；不把这当内部确定性的证据。每工作进程单 BLAS/OpenMP 线程；最多 600 秒墙钟。版本、库哈希、输入、日志、耗时均登记。
- 首次完整返回 ndarray 立即排他写入 `.npy`、fsync 并记录 SHA256，再做任何效果评估。结果不佳不得重跑；超时无完整输出为 UNKNOWN。异常或输出契约错误为 IMPLEMENTATION_ERROR；不采用部分矩阵。任何网络任务创建接口均不应由本地 mutate 调用触达。
- 输出须形状 105×105、有限、对称、零对角；不事后对称化／修复。随后按原统一 N8 缩放及最近偶数取整产生 K，完整浮点输出与 K 均保存。
- G1：独立 `checker.py`（不导入建模模块）完整整数验能并排除非法状态，包含禁选 one-hot；所有全局最优须业务可行。每项认证至多 10^6 节点／600 秒，超时 UNKNOWN。
- G2：全部允许整数最小能量解的最坏原表 regret≤0.1。G2 单独报告 PASS/FAIL；总体验收四状态保留 CERTIFIED/COUNTEREXAMPLE/UNKNOWN/IMPLEMENTATION_ERROR，G1 通过但 G2 失败归整体 COUNTEREXAMPLE，不能丢弃此候选。
- 一项或两项过双门：按 v2 顺序选最小最坏原 regret、最大 Top-20 保守保留率、N8 优于 M8（本路径均 M8）、配置 ID 字典序。不看任何新 SA。锚定唯一矩阵，取消路径乙，走获批先导。
- 无双门候选：甲封档后启动乙。仅 G1=CERTIFIED 且 G2=FAIL 的甲输出进入乙的附加候选池；未知、非法反例或实现错误的甲输出不加入。两发结果齐备即向用户及侦察兵同步。

## 3. 路径乙：固定八格的探索性研究

仅当甲无双门通过者启动。网格恰为 λ∈{λθ,λR} × encoding∈{raw,rc} × forbidden_fill∈{R,2R}，没有其他维度或动态扩展。λ 固定为上节两个数，填值 2R 后不重新计算 θ 或调大 λ。

八格中的 λθ/R 两格直接复用 rescue1 的整数矩阵；λR/R 两格直接复用 v2 的整数矩阵；其余四格只变禁选填值。所有格重新导出的 real J 和复用 K 必须逐元素核对。记录每格 max|J|、统一缩放因子、量化步长 max|J|/127、参考边最大值、整数唯一系数数目及证书状态。

填值 2R 是针对已知反例的新假设，不能预先宣称有效：它可能抬高 max|J| 而加重舍入。旧 raw 的禁选 witness 与 rc 的 A0/B3 witness 属于不同类别，不能都解释成禁选 one-hot。

附加池至多包含甲中两项 G1 通过而 G2 失败的矩阵，不给这些矩阵再调用 mutate。这些附加项与八格采用相同 SA、筛选和完整披露规则，单列来源，不冒充原八格。

### 3.1 固定 SA 预算与返回合同

- 每个可执行候选恰好 1,000 次独立重启，10 块×100。最多八格加两附加项＝10,000 次；没有失败后的补跑。即使原格已有 SA，也执行本轮一致的固定 1,000 次协议，旧实验不覆盖、不合并。
- 使用 v2 **主温度**：S=4max_i Σ_j |K_ij|，初温 S、终温 10^-4 S；alpha=.99，iterations_per_t=10，size_limit=1，process_num=1。只有这一温度方案，不加额外温度维度。
- 种子为 230026+100b+r，b=0…9，r=0…99，各格共用种子序列；最多四个外层 CPU 工作进程。GPU 不参与。API 返回必须为一行 105 个 ±1 自旋；失败／异常完整留账且计入 1,000 的分母。
- 每样本独立解码；可行要求两组各恰好一个且 mask 允许。原始样本、整数能量、组成和原 regret 全保存，不做修复。

### 3.2 指标和选择规则（先冻结）

1. 主可行样本率=有效且业务可行返回数/1,000；并列报告有效返回率及条件可行率，不能将计算失败移出主分母。
2. 全部可行样本的原 regret 分布单列为**条件分布**；全任务无解块比例另列。
3. 每块从可行样本中取**整数能量最低**者；同能量按既有组成 SHA256，再按重启序号打破并列，禁止拿原 regret 择优。随后查原表计算该解 regret。没有可行解的块记失败、选择中位数时记 +∞。
4. 主块成功率=所选可行解 regret≤2 的块数/10；同时报告块内存在原 regret≤2 样本的概率作为 oracle 诊断，不用其替代主指标。
5. 入围必须主可行样本率>10% 且十块所选解 regret 的中位数≤2。偶数中位数采用第 5、6 排序值的均值；任何参与无穷大则为无穷大，不先剔除失败块。
6. 入围后取主可行率最高者；若完全相同，按预先固定配置 ID 字典序（包括甲附加项）确定。该 tie 不新增性能指标或调整规则。
7. 无入围项：本次探索硬件路线停止；不扫其他维度、不动 split，不写“纯审计论文”，仅保存技术结果等待用户另行授权。

路径乙的 G1 证书如为 COUNTEREXAMPLE/UNKNOWN 必须照实保存；用户本轮允许的是过滤可行返回的**探索性硬件实验**，不把这类矩阵改称确认性认证通过。没有“CIM 显著优于 SA”、真实筛选准确率或材料有效的确认性宣称。八格、附加项、失败格、全部选择成本均公开保存；“入论文”仅作为以后单独获准撰稿时的要求，现在不写论文。
