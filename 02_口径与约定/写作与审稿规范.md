# APMCM 写作与审稿规范

> 本文件是项目级口径；深度规则见 skill `references/09_写作与审稿项目规范.md`、`11_验证与结果叙事.md`、`13_评分与专家评阅.md`。
> APMCM 官方规则/模板优先；不要把另一赛事的页数口径、页眉格式、AI 阈值直接套过来。

## 1. 装订层先确认

- p1 Summary；p2 Contents；正文 ≤25 页；附录不限。
- 页眉 `Team #<team number> Page <x> of <y>`。
- 正文/图题/表题/图例/坐标轴全英文。
- Control Sheet 单独签名提交，不进论文。
- 无姓名/学校/指导教师/邮箱。

## 2. Summary

- 一页；不跨页；无公式/图/表/引用角标。
- 每问至少：方法 + 一个结果数字 + 条件/边界。
- 目标 350—450 词、10—25 个关键数字（经验参考，不是官方门槛）。
- 不写“首先/然后/接着”的流程记录；不写空泛评价。
- 摘要数字必须与正文/结果 CSV 同版。

## 3. 正文

每问按：

```text
Problem analysis → Assumptions/notation → Model → Solution → Results
→ Validation/sensitivity → Direct answer → Boundary
```

- 每节开头先给判断句；关键结论不要埋在长段最后。
- 每问有 Direct answer，3—6 句回答题目原话。
- 问题重述不抄题；至少写一个歧义/隐藏条件及处理。
- 每条关键假设有依据、范围、失效影响。
- 模型选择写“问题结构→候选→理由→代价/边界”，不只写“采用 XX”。
- 结果先写结论，再数字/比较，再含义/边界；绝对差、相对百分比、百分点分开。
- 不只报有利结果；失败案例、覆盖率不足、代价要写。

## 4. 审稿输出

```markdown
# APMCM Paper Review
- Paper/version/pages/body pages:
- P0:
- P1:
- P2:
- Number check: summary ↔ body ↔ table/figure ↔ CSV
- Verdict: submit / revise / block
```

每条问题写：位置、观察、影响、修复、复验条件。不要写“加强模型/提高美观”这种空话。

## 5. 停止条件

1. 正文 >25 页且只能删关键结果 → 先压缩重复叙述，不删证据。
2. Summary 与正文数字冲突 → 回源 `key_numbers.csv`。
3. 只剩润色且时间 <3 h → 停止改模型，只做格式/提交。
4. 题号/队号/文件名/页眉不确定 → 查官方，不要猜。
