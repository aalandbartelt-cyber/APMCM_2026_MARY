## 2. 悬案一：自动罚系数是否与旧系列同源？

**结论：同源，且可以追到当前安装的具体调用链；并非额外的全局优化定理。**

印刷p43讲“目标翻转变化上界 / 罚项最小非零变化”的比值，p44示例直接调用 `kw.core.get_min_penalty(obj, cons)`。当前安装的 `kaiwu/core/__init__.py` 从 `_constraint.py` 导出这四个同名入口，均属于community1.0.8：

```text
get_min_penalty(obj, cons)
  ├─ obj.get_max_deltas()
  └─ get_min_penalty_from_min_diff(cons, negative_delta, positive_delta)

BinaryModel.initialize_penalties()
  ├─ hard: get_min_penalty_from_min_diff(compiled_penalty, ...)
  └─ soft: get_soft_penalty(...)（平均系数比例）

get_min_penalty_for_equal_constraint(obj, linear_residual)
  └─ 独立计算目标翻转界 / 线性系数平方

get_min_penalty_from_deltas(..., min_delta_method="diff")
  └─ diff 或 exhaust 的另一条罚项变化估计路径
```

`get_min_penalty` 没有自动在equal、diff、exhaust三路中选择“最强证明”。`from_min_diff` 使用罚表达式系数、相反数和0的最小正间距作估计；它不是穷举整个业务状态空间得到全局最小λ。`from_deltas`默认diff仍仅考察0/1/2个邻接项取1来估计最小变化；exhaust覆盖更多局部组合，但也不等于全业务模型的全局可行性证明。

p67对 `get_min_penalty_for_equal_constraint` 明确限定“一位比特翻转的局部意义”，从线性残差计算其平方罚项的变化尺度。多约束同时变化、不可行局部极小、松弛变量范围和有限精度下的可行性仍需独立处理。返回临界系数时也可能产生能量平局，不能将“最小”读成严格排除所有不可行全局最优。

**调用者必须先说明cons的语义。** 自动系数不负责将任意符号残差变成非负罚项。模块p66的示例使用 `cons=sum(x)-1`；若直接照“obj+λcons”拼接，取其例 `obj=x1+2x2, λ=2`，全零态能量−2，满足恰选一的第一位单选态能量0，说明线性残差不能直接充作该约束的非负罚项。这是代数反例，不是运行SDK的结果；p44示例本身用平方项加非负项，二者应区分。

因此旧 `max(W)+1` 的松紧仍应按本题结构证明、再验证，而不是直接用一个自动返回值取代证明。本轮根报告针对非负两块one-hot的λ定理保持有效；没有进行新λ扫描，也没有调用上述任何函数。

## 3. 悬案二：p31精度章与PrecisionReducer的关系

**结论：p31—42是四种精度方案的总章，PrecisionReducer正是第4种组合封装，不是另外一个无关功能。**

| 方案 | API | 当前文档支持的判断 |
|---|---|---|
| 直接缩放取整 | `adjust_ising_matrix_precision`；QUBO包装版本 | 简单且可能严重损失；后者先转Ising再调精度再转回，不只截QUBO元素 |
| 动态范围压缩 | `perform_precision_adaption_mutate` | 以保最优的系数改变为目标；明确不保证一定降到指定精度，需检查实际输出 |
| 拆分 | `perform_precision_adaption_split` | 位宽、分辨率、维数与还原要共同记录；1.4.4支持var和item |
| 组合装饰器 | `PrecisionReducer(component, ...)` | 截断与拆分自动组合；文档没有说明它会自动调用mutate，不能将四者混称同一算法 |

以p101—103模块定义为准：

```text
PrecisionReducer(component,
                 precision=8,
                 target_bits=None,
                 only_feasible_solution=False,
                 truncated_precision=20)
```

- `precision`是目标系数位宽概念；例子用4/8。API说明某处称“小数位数”不宜据此理解成保留8位小数。
- `target_bits`是目标矩阵比特数/维数上限，默认None，不是动态范围上限。p42正文将两者混称，不能沿用该句。
- `truncated_precision`控制预截断精度；截断后再split，仍不能满足目标时可直接截断到目标精度。故有官方Reducer不等于原目标无损，也不等于在给定维数内一定保留原最优。
- `only_feasible_solution=False`为**1.4.4文档默认值**。True的检查针对拆分约束，不能代替one-hot/盲池成员约束/真实材料五条件；全部拆分不可行可抛异常。False容许还原存在副本不一致的候选，必须显式再验业务可行性及原vhat。
- `solve(..., sort_solutions=False)`默认不排序；所有候选仍应按原目标重算、验证后挑选。QuboSolver的排序路径另论。

与1.3.1的精度流程可以作历史对照，但当前私有精度核心为`.so`，本轮没有执行或完整审查其内部实现。新的API描述和默认值以本汇编优先，不能把1.3.1边界Bug宣布为1.4.4已验证Bug。

## 4. 1.4.4增量：项拆分、索引与两层可行性

`perform_precision_adaption_split(..., param_bit=8, min_increment=None, penalty=None, round_to_increment=True, method="var")`：

- `var`复制变量并以罚项约束一致；`item`保留原变量、为项增加辅助自旋，不使用该副本一致性penalty。
- `min_increment`默认是系数不同值的最小正差，不是最小非零绝对系数；增大它可能引入系数近似。返回矩阵可以整体除以步长后才满足位宽，不必每个原始数值都落在整数区间。
- p107明确：var返回每个原变量**最后副本**的位置；item保留原变量在矩阵前部，索引为`0...n−1`。新版已把此前某旧文档的“第一次出现”表述改正。
- 原参考自旋也要通过映射恢复，不能在新增辅助自旋后直接把“最后一位”当原参考位。先restore到原Ising维度，再按原参考位解码 (x_i=(1+s_i s_{ref})/2)，最后检验业务池成员和约束。
- 拆分的局部数学等价、硬件退火是否找到相应低能态、还原后的业务可行性、真实材料可行性是不同层次，分别留证。

这使“拆分方案”不能只按旧复制变量方式讨论；未来对比应把var/item分别记录。但本轮没有实现两者，也不据文档示例裁决哪种在D题更优。

## 5. 汇编可检索，但公式与代码不能盲复制

关键页视觉核对确认以下不是单纯pdftotext造成的问题：

1. p36的DR文字/公式把“最大/最小距离”写成系数绝对值；p103模块却明确定义为**不同系数之间的最大差/最小正差**。有零值时，两种定义尤其不同。按p103；旧1.3.1可读utils只作交叉证据，不冒充当前1.4.4私有utils源码。
2. p38把 (M(s-s')^2) 展开为 (-M(2ss'+2))，正确为 (2M-2Mss')。对优化只差常数，但报告绝对能量/offset时会错；同页先写正J目标，后面的项拆分证明出现负J，须统一Kaiwu负哈密顿量 convention 后再使用。
3. p43“1→0”目标增量的右端负系数和缺少取负号；对任一负系数，翻转造成正增量，不能被负数上界。不能用这行式子直接推导λ；当前源码的 `get_max_deltas` 才是具体计算路径。
4. p42正文把target_bits与动态范围混称；p101还有“split降维”的表述，而拆分实际增加变量。以参数定义/映射和实算维数为准。
5. 文档含可见HTML实体和幂符号/缩进损失；如p44/p137中的Python平方在汇编里呈`(...) 2`。代码是阅读依据，不按PDF文本自动执行。案例中的1.66ms或速度图也不能不加边界地当端到端成本/本题量子优势。

以上不否定新汇编作为1.4.4首查资料的价值；它让API关系更明确，也让内部矛盾更容易核查。正式使用某公式时需回到同版API、可读实现与独立数学证明；旧HTML只作差异/原式补充。
